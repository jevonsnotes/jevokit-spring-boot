# 提交文稿与 commit message 不得包含前身定制项目名

- 分类：沟通/流程
- 状态：已认可
- 适用范围：所有进入 git 仓库的文件（CHANGELOG、README、docs/、openspec/、代码注释、证据留档等）与所有 commit message

## 偏好描述

所有将提交到仓库的文稿（文档、注释、提案、示例、证据留档）与 commit message，一律不得出现前身定制版本的任何标识——项目名、包名、配置前缀、Maven 坐标、项目头注释及其派生称谓均不得出现，本条自身亦不复述其字样。表述前身相关事项时使用中性说法，如"前身定制版本""历史定制分支""旧版内部定制（2.7.2.x 线）"。

## 认可场景

2026-10-13，用户在 2.7.x 降级交付的 commit 编排前明确指示：所有提交文稿（含 commit message）不得出现前身定制项目相关内容。同日据此完成 2.7.x 工作区文稿与证据留档的全面脱敏。

## 反例（什么算违背）

- CHANGELOG 迁移指引指名出现前身项目名，或给出未脱敏的旧坐标/旧配置前缀映射
- commit message 出现前身项目名或其派生称谓
- 文档/注释/证据留档中出现前身包名、旧配置前缀、前身项目头名、前身同形本机用户名等标识

## 参考实现

迁移说明统一用中性表述（"从旧版内部定制版本升级时……"）；坐标/前缀对照表用通称形式（"旧版工具模块 → jevokit-core"，或按功能域给出 jevokit 侧前缀）；证据留档中的本机用户名等前身同形字样以中性占位（如 operator）替换，并附脱敏说明留档。
