# 偏好沉淀库（Preferences）

> 本文件由 team-creator 技能生成。它是**索引 + 使用说明**，具体偏好沉淀在本目录下的各条目文件里。

## 这是什么

用户认可过的风格、偏好、约定的沉淀库。它是项目级的"用户审美/习惯记忆"——把用户每一次"对，就这样"或"不要这样，应该……"沉淀成可复用的标准，避免用户就同一个偏好反复纠正团队。

**与 `../lessons/` 的分工**（两者都是项目级知识库，但方向相反，不要混）：

| 库 | 记什么 | 目的 |
|---|---|---|
| `docs/lessons/` | **"错"**——bug 根因、踩坑 | 防范复发，不再踩同一个坑 |
| `docs/preferences/`（本库） | **"对"**——用户认可的风格、约定 | 主动复用，不再就同一偏好反复纠正 |

## 团队开局必读 + 实现前必读（核心机制）

- **领导**：新会话第一次派活前读本索引，把相关偏好纳入派发指令（和读 `lessons/` 并行——教训防犯错，偏好保一致）。
- **开发 / UI 工程师**：每次实现/出稿前，查与本任务相关的偏好条目，主动遵循。这和"复用优先"（复用代码）同源——复用代码避免重复造轮子，复用偏好避免重复纠正。

## 偏好分类法

每条偏好归入下列分类之一，便于检索和发现用户审美/习惯的一致性：

| 分类 | 典型内容 |
|---|---|
| UI/视觉 | 布局、配色、间距、字体、组件用法、图标风格 |
| 交互 | 动效、反馈方式、状态流转、错误提示、表单行为 |
| 代码风格 | 命名、分层、错误处理、注释、目录结构、日志风格 |
| 接口风格 | RESTful 约定、字段命名、错误码、分页、版本管理 |
| 沟通/流程 | 汇报格式、commit 规范、文档习惯、评审流程 |
| 其他 | 上述之外 |

## 单条目骨架

新建 `pref-<简述>.md` 时，按以下结构写。**关键是"认可场景"和"反例"**——光写"用户喜欢简洁"无法操作，要写"用户在 X 页面认可了 Y 做法，违背的表现是 Z"，工程师才有判断标准。

```markdown
# <偏好标题>

- 分类：<上述分类之一>
- 状态：<已认可 / 待确认>
- 适用范围：<哪些场景/模块适用>

## 偏好描述
<用户认可的做法是什么，具体到可执行>

## 认可场景
<哪个页面/模块、用户怎么说的、什么时候>——这是这条偏好的出处，便于追溯。

## 反例（什么算违背）
<违背该偏好的典型表现，让工程师能快速判断"我是不是又踩了这条">

## 参考实现
<认可时的代码位置/截图/设计稿链接，作为对照标准>
```
